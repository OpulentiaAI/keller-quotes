A runtime-root mismatch can prevent tool discovery before the service returns a tool response.
The original startup evidence in [[Keller retained reissue learning evidence]] records a launch path missing a directory component and a coordinator reproduction with that nonexistent path.
The correctly pinned path retrieved the tool schemas against the same daemon.
That comparison rules out service unavailability and credentials as the demonstrated cause of this specific failure, not of every future discovery error.
Repeating an unverified path unchanged supplies no new health evidence.
