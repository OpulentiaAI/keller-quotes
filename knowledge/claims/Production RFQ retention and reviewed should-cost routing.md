- **Retain first:** explicit operator upload capture uses `estimator/src/intake-cli.ts` / `intake.ts`. Original JSON and attachment bytes are retained in new owner-only immutable-by-interface directories with SHA-256 locators. Preserve original UOM, drawing/part revision, page/record/field evidence, applicability and unknowns. Extracted text is untrusted, not verified geometry. This is manual capture, not automated email/CAD interpretation. Changes require a new capture; the supplied structured request must still reconcile to original retained input.
- **Choose the price basis deliberately:** `requiresHistoricalRegister` in `estimator/src/order.ts` validates before routing. ALL lines using supported `unit_price`, `cost_plus` or `should_cost` may omit corpus/register. Native `arsumbris/quote/tool.ts` then skips Polygres entirely and reports null corpus/register hashes, not invented provenance. Historical/mixed requests require an explicit register/corpus; evaluation scopes retain their separate enforced binding. Do not feed archive sale prices to landed material cost or present a metal benchmark as a delivered buy offer.
- **Cost supported assumptions:** `estimator/src/costing.ts` records source dates, original units/conversion, yield/minimums, setup/run quantities and COST rates, exclusions and estimate approvals. Optional `engineering_fact_ids` ties worksheet entries to reviewed supported/assumed facts; unknown/conflicting facts cannot justify a cost entry. All `keller-intake:` cost references (including scope exclusions) must bind a captured attachment's hash/locator; unresolved `upload:` references cannot reach quoting. External estimates stay explicitly unauthenticated. `should_cost` derives the existing cost-plus inputs and applies gross margin once: sell = cost / (1 - margin). Absence is not zero. Unsupported costs require concrete evidence/approved estimates, never invention.
- **Read retained evidence within bounds:** `arsumbris/sources/read.py` resolves explicitly named same-stem FPT text only with `memo_fields` and `fpt_path`. Default DBF null memos mean unresolved. Pin DBF/FPT hashes across bounded continuations, retaining pointer/record offsets. Missing files, unsupported format, decode errors and empty pointers are distinct. None authenticates finished geometry or applicability. Operator launcher `scripts/start-arsumbris.mjs` validates source roots/Python and strips private source binding from engine/blinded worker environments.
- **Review, never release:** `order-cli.ts` and native `keller_quote` recheck retained input bytes; private artifacts retain original input links, costing assumptions, request hash and named reviewer. Complete arithmetic without explicit engineering conflicts remains `PRICED_REQUIRES_REVIEW`; missing price/shipping/tax or any explicit engineering conflict remains blocked (including facts not linked from a worksheet). Numeric comparisons survive the hold; unknown/assumed facts retain uncertainties. Neither names nor hashes authenticate approval. `customer_release_authorized` stays false; independent scope/cost/freshness challenge and named human review precede any separately approved delivery process.

- **Discover candidates, not automatic costs:** exact-ID `dbf_rows` remains available. When an ID is unknown, `dbf_schema.catalog_lookup` advertises bounded `dbf_catalog` browse/literal search only for MATERIAL, OPERATIO and FORMULA definitions. Preserve source hashes and physical locators; pin the DBF hash on continuations. Candidates are not automatically adopted as stock, routing or rate inputs: review applicability, units, COST/SELL meaning and freshness. See `docs/arsumbris-workspace.md` and the canonical quoting skill.

- **Whole-stock purchase assumptions:** optional component `purchase_increment` rounds requirements up in original priced units after yield and minimum quantity, before unit cost and minimum money. Omission preserves fractional allocation. A kg-priced sheet needs its supported kg-per-sheet increment, not an inferred increment of one. Review pack/stock applicability and leftover allocation; no inventory credit, cross-line sharing, automatic tier selection or change to routing/shipped quantities is inferred. The costing breakdown preserves the pre-increment quantity and supplied increment for named review.
