# Worker-context integrity correction

The source-scope guard protected business-evidence routes but did not ensure that permitted instructions were free of prior evaluation outcomes. A fresh worker stopped after receiving historical aggregate scores in the allowed pricing/order guide. Inspection of the actual delivered MCP responses confirmed the same exposure in **all six new attempts** and **all 18 earlier baseline/startup/matched attempts**.

This is evidence of **prior aggregate-score exposure**, not evidence that the hidden target prices were delivered through that paragraph. It does not establish that those scores caused any particular pricing decision. The earlier numerical errors, criterion transitions and raw original grades remain unchanged, but those attempts cannot be described as cleanly blinded to prior results.

## Information channels and disposition

- The allowed `docs/pricing-evals-and-orders.md` mixed the order contract with an earlier 50-case experiment's measured errors and pass counts. The canonical evaluation skill also disclosed qualitative outcomes from a pricing experiment. A valid file path was therefore not a sufficient context boundary.
- The frozen private rubric's operator-only `limitations` metadata referenced an earlier score. It was a permitted direct worker/judge input, independently of the MCP file guard. This identifies a second exposure channel; the raw MCP records alone do not prove which direct-file text each worker read.
- The new six-attempt batch was stopped, its raw and partial artifacts preserved, and all six attempts retained as protocol-invalid. Five had already generated preliminary quote responses; none is promoted to a clean evaluation result. They are additional attempts on three repeated and three additional development RFQs, not replacements for the earlier attempts or independent confirmation cases.

Worker-readable files now carry normative evidence, arithmetic, input and review requirements, while historical measurements and evaluation operations belong in an [operator-only guide](pricing-evaluation-operator-guide.md). The original empirical paragraph is preserved there, not deleted or rewritten. The existing fixed file allowlist is not widened.

Workers and judges must receive a frozen normative rubric view that preserves the original version, population, weights, acceptance rule and all ten criterion definitions unchanged, while omitting operator metadata. Retain the original rubric bytes and both source/view hashes. A projection is not permission to weaken a criterion or silently redact arbitrary criterion prose: the actual delivered view still requires a content audit.

## Verification and limits

Before restarting, inspect every allowed skill/contract and direct input as actually delivered, verify that operator-result files are denied, and freeze the visible prompt/rubric/skill versions. Use fresh worker and judge contexts; do not resume exposed contexts and pretend they forgot the results. Keep missing, aborted and invalid attempts in the ledger, with original scores and later integrity annotations separate.

This correction does not repair the separately contaminated confirmation set. New development scopes globally exclude the reserved quote, document and PDF identities, but the original confirmation replacements still require their own clean refreeze. No accuracy gain or recovery of criterion losses follows merely from separating context channels.

The [repaired-context development iteration](blinded-iteration-two-results.md) preserved all criteria and original judgments but still produced no adopted final prices. It also exposed a separate chronology limitation: inquiry/header date agreement did not account for a later printed PDF version. Context separation and metadata-based cutoff checks are distinct controls; passing either alone does not establish clean historical eligibility.
