# Private MCP trajectory analysis and learning

Use this operator workflow for each Keller three-question MCP evaluation iteration, including the [exact-reissue](mcp-workflow-evaluations.md) and [blinded historical](blinded-mcp-workflow-evaluations.md) populations. It supplements, but does not regrade, their separate V1–V5/J1–J5 contracts. Keep source requests, session snapshots, audits, answers, grades, comparisons and learning packets in owner-private storage outside Git. A public results summary may report aggregate findings without customer details, source paths, target prices or private traces.

## Freeze and collect before analysis

Before each batch, freeze the same ten criteria, complete request bytes and hashes, selected case IDs and their corpus/oracle/scope hashes, as applicable. Record the executable/checkout revision, runtime and lockfile versions, working-tree **content** hashes of skills actually read, model/effort and MCP configuration. HEAD alone does not attest to uncommitted skills; the retrospective analyzer cannot reconstruct what a worker saw. Record each attempt's run/case ID and validity separately, including held, failed and invalid attempts. Preselect untouched confirmation cases before changing guidance.

For each fresh worker capture the original prompt, session and child identifiers if available, observed conversation messages, complete delivered MCP call/response audit including errors and ordinals, and persisted artifacts. Retain a private session snapshot if the host permits it. Mark coverage explicitly: a recent-only message export is **recent-only**, not a complete session; unavailable child history, event classes or tool responses are unavailable, not silent successes. Do not invent internal reasoning, elapsed durations, missing calls or an event timeline from a final answer. Distinguish an agent's account of its actions from observed tool output. Keep each attempt's raw evidence and exact byte hashes immutable; do not replace an invalid attempt with a cleaned-up rerun.

Seal the worker's answer, audit, artifacts and session snapshot **before** independent judging. A fresh judge sees the frozen request/oracle, final artifacts and complete available MCP audit, never worker reasoning, prior verdicts or a desired score; keep its raw verdict and SHA bindings. Grade a criterion only when its actual artifact and judge evidence support it. Missing or partial coverage is a limitation or invalidity, never a fabricated per-turn J verdict. Run the appropriate independent grader from the evaluation contract, then analyze only the sealed inputs and grade.

## Build a cited private timeline

For each attempt, map the observed prompt/messages and audit ordinals into searches, pagination, page reads, candidate/source evaluation, quote requests and responses, tool errors, quote revisions and final handoff. Cite the exact message/artifact or audit ordinal for each observation. A reported decision is attributable to the worker only when recorded in its statements or submitted inputs; otherwise say what the tool output shows and leave intent unknown. Treat unobserved events and incomplete transcript segments as unknown. Check attachments or persisted drafts when relevant, especially whether the delivered draft equals the final successful tool response.

Attach the existing [blinded per-turn price diagnostics](blinded-mcp-workflow-evaluations.md#private-per-turn-price-diagnostics) by observed quote ordinal after the run: show proposed unit, target unit, signed error, absolute percentage error, extension mismatch, and the changing direction and magnitude across revisions when valid finite prices exist. Keep the denominator of finite-priced lines separate from attempted cases. A held, malformed or missing price has no numeric error, not zero error. Tie later criterion findings to the earliest *supported* relevant turn, not an imagined reasoning step; the final V/J criterion verdict still comes from the grader/judge on the actual artifacts. Targets, errors, comparative analyses and learning packets remain private and must **never** return to a live blinded worker.

The operator may run the artifact freezer/comparator on private files after grading:

```sh
python3 scripts/analyze-mcp-trajectory.py \
  --manifest "$PRIVATE_CANDIDATE_MANIFEST" \
  --baseline "$PRIVATE_BASELINE_MANIFEST" \
  --out "$NEW_PRIVATE_TRAJECTORY_JSON" --fail-on-regression
```

For one attempt, omit `--baseline` and `--fail-on-regression`. Manifest v1 has `schema_version: 1`, `run_id` and `case_id`; it maps `artifacts.request`, `criteria`, `answer`, `audit` and `grade` to `{path,sha256}`, and records an `execution` metadata object and `validity: {status,reason}` with status `valid`, `invalid` or `unknown`. Record `execution.checkout`, `execution.model` and `execution.skill` as nonempty strings when historically observed: checkout and model identify those actually used, and skill identifies its recorded working-tree content, not current HEAD. Never fill an absent historical value from today's checkout; leave it unknown and disclose the comparison limit. Optional `artifacts.session` references an operator-captured JSON snapshot, whose recorded coverage must be described accurately in execution metadata; a recent-only snapshot stays recent-only and no snapshot means unavailable. Use absolute paths in a private directory and hash the exact bytes supplied. The analyzer reports observed audit ordinals and compares supplied grades; it does **not** interpret the session snapshot, attest original execution, reconstruct missing messages or prove why a decision was made. The operator must build the cited narrative above from the retained sources. Preserve output alongside original inputs, not in Git.

## Compare matched attempts and investigate losses

Compare baseline and candidate only with identical case/request/rubric and relevant population/target basis. Show all attempts and validity/coverage, each case's ten baseline and candidate criterion verdicts/reasons, total gains, and **every pass-to-fail criterion loss** separately. An aggregate-score increase never cancels a loss. Invalid, missing or incomparable evidence is not a nonregression pass. Report the earliest cited divergence for each loss, the baseline and candidate evidence, competing explanations (e.g. altered prompt/skill, changed evidence eligibility, tool failure, judge inconsistency or different execution), and what was checked to rule each out. If the trace is incomplete, say which hypothesis cannot be tested. Recommend a user-controllable remedy—prompt, scoped guidance, runtime/environment or MCP configuration—and the matched verification that would test it. Do not convert a correlation into a cause without observed sequence, a plausible mechanism and ruled-out alternatives.

The same development cases can debug a proposed change but cannot independently validate it. Re-run on the preselected, fresh, globally isolated confirmation batch with unchanged criteria and blind boundaries; preserve failed and invalid runs. Model outputs are stochastic: no finite batch guarantees deterministic nonregression, so describe the observed loss and uncertainty rather than weakening criteria, rerunning until lucky, or claiming false success. Small three-case results characterize only those selected cases, not general price accuracy or commercial outcomes.

## Promote only verified, reviewed learning

Use source observations or verified documents as facts; label agent narrative as a claim until corroborated. Draft zero to ten candidate snippets, each at most 300 characters, with a specific Keller scope, provenance citation and explanation of when it helps. Exclude credentials, customer data, oracle/target answers, holdout findings, speculative pricing prescriptions and one-off anecdotes. A candidate must be reusable and testable, not a disguised result from a private case.

Give the **complete** candidate batch to exactly one independent reviewer with no source transcript, write access or requested verdict. Require one JSON verdict per numbered item, uniquely indexed, with a case-sensitive uppercase `ACCEPT` or `REJECT` and a reason. Missing, malformed, duplicate or conflicting results reject affected items; reviewer failure, timeout or no usable verdict rejects all. Do not retry, solicit a more favorable verdict or revise a rejected item into an implicit acceptance. Zero candidates or zero accepted is valid.

Before using an **unchanged** accepted item, verify its cited evidence independently, then compare with current scoped instructions. Record a disposition for duplicates/conflicts: keep the new item, reject the redundant item, or deprecate a superseded instruction with a reason. An evidence-backed, reviewed candidate may enter versioned, scoped repository guidance as a **proposed change for development testing**, with its provenance and unvalidated behavioral-improvement status explicit. Development reruns test that change; claim measured improvement or promote it as production-proven only after clean independent confirmation. Never auto-write global memory. Store the private candidate packet, review verdict, provenance, duplicate disposition, guidance diff and verification links together so a later operator can audit what changed. A rejected item is retained in the packet but never silently edited or promoted.
